Sandbox.jl

Sandbox.jl runs commands in a root filesystem of your choice, with the host paths you choose mounted in it, on Linux, with user namespaces. See the README for an introduction.

Sandbox.SandboxConfig — Type
SandboxConfig(; rootfs, mounts=[], defaults=true, env=Dict(), cwd="/", uid=0, gid=0,
              hostname=nothing, persist=nothing, tmpfs_size=nothing, mode=:userns,
              multiarch=Platform[], verbose=false)

What a sandbox is made of. Sandbox.command turns it and a command into a Cmd that runs the command in it.

  • rootfs: the host directory that is the sandbox's /. The sandbox sees an overlay of it: its changes go to persist, not to rootfs.
  • mounts: destination => mount pairs, mounted in order after the default mounts (see Sandbox.default_mounts); each mount is a Bind, Overlay, Tmpfs or Symlink. A later mount at the same place covers an earlier one. A dictionary is mounted parents first. A mount at or above a default mount's destination replaces that default.
  • defaults: whether to start from the default mounts.
  • env: the environment of the command, to which that of the command itself is added.
  • cwd: the command's working directory, created if it doesn't exist.
  • uid, gid: who the command runs as, root by default. Whatever the ids in the sandbox, files are created as the calling user on the host.
  • hostname: the sandbox's hostname.
  • persist: a directory that keeps the changes to the rootfs and to the overlays, for a later sandbox with the same directory to see. It belongs to the caller, who creates it and removes it, and only one sandbox may use it at a time. See Sandbox.probe_persist. Without it, changes go to a tmpfs and are gone when the command exits.
  • tmpfs_size: the size of that tmpfs, "1G" by default.
  • mode: :userns sets up the sandbox in a user namespace, without privileges. :sudo sets it up as root, through sudo, for kernels that don't allow an overlay in a user namespace; the command still runs as the calling user.
  • multiarch: platforms whose executables the sandbox should be able to run, through QEMU. Sandbox.register_multiarch registers what that needs with the kernel (run does so itself).
  • verbose: have the launcher tell what it sets up.

Sandbox.command — Function
Sandbox.command(config::SandboxConfig, cmd::Cmd) -> Cmd

The command that runs cmd in the sandbox config. Run it as any other, with run, pipeline, open or read: its standard streams are those of cmd in the sandbox. It exits as cmd does, or with 125 if the sandbox could not be set up, 126 if cmd could not be executed, and 127 if it was not found.

cmd's executable is a path in the sandbox, not looked up in its PATH. Its environment is config.env plus that of cmd, and nothing else; ignorestatus, detach and cpus carry over. cmd can't have a dir: the working directory is config.cwd.

This has no side effects. Unlike run(config, cmd), it doesn't register the interpreters for config.multiarch (see Sandbox.register_multiarch).

Base.run — Method
run(config::SandboxConfig, cmd::Cmd; wait=true)

Registers the interpreters for config.multiarch, if needed, then runs cmd in the sandbox. Shorthand for run(Sandbox.command(config, cmd); wait) after Sandbox.register_multiarch(config).

Mounts

Sandbox.Bind — Type
Bind(source; writable=false, devices=false, optional=false)

The host path source (a directory or a file), including the mounts below it.

  • writable: writes go to source; otherwise it is read-only, including the mounts below it.
  • devices: device nodes in it work, as for /dev/kvm or a GPU. Otherwise they can't be opened. Setuid bits never take effect.
  • optional: skip it if source doesn't exist, rather than fail.
source
Sandbox.Overlay — Type
Overlay(source; readonly=false)

The host directory source, with changes that go to the config's persist directory (or are gone after the run without one) instead of source.

The changes are kept per destination: with readonly=true, an overlay shows (read-only) what an earlier overlay at the same destination wrote to the same persist directory, over source.

Tmpfs(; size=nothing, mode=0o755)

A fresh tmpfs, of at most size bytes (an integer, or a string such as "1G" or "50%" of the memory; by default, half of the memory), whose root directory has permissions mode.

Sandbox.CgroupView — Type
Sandbox.CgroupView()

The sandbox's cgroup, read-only, as the root of a cgroup2 hierarchy: limits can be read but not changed, and no other cgroup is visible. On hosts without cgroup2, an empty read-only directory.

Sandbox.default_mounts — Function
Sandbox.default_mounts()

The mounts every sandbox gets before those of its config, unless it says defaults=false: a fresh /dev with the usual device nodes, pseudo-terminals and /dev/shm, the host's /sys read-only, and a read-only view of the sandbox's cgroup. (/proc is always the procfs of the sandbox's PID namespace.)

Persistence

Sandbox.scratch_persist_dir — Function
Sandbox.scratch_persist_dir() -> String

A new directory in Sandbox.jl's scratch space, to use as a persist directory. It is the caller's: nothing removes it automatically. The scratch space is in the Julia depot, which can be on a filesystem that can't hold the changes of an overlay (see Sandbox.probe_persist).

source
Sandbox.probe_persist — Function
Sandbox.probe_persist(dir; rootfs=Sandbox.debian_rootfs(), mode=:userns, verbose=false) -> Bool

Whether persist directories in dir work with this kernel, filesystem and mode: overlayfs needs extended attributes and whiteouts on the filesystem of dir, which some (such as ZFS, or another overlayfs) lack, and some of which a user namespace may not create. Runs two sandboxes of rootfs with a new directory in dir, which it then removes.

source
Sandbox.remove_persist — Function
Sandbox.remove_persist(dir; mode=:userns)

Removes the persist directory dir, which no sandbox may be using. overlayfs leaves directories in it that can't be read (mode 000), so this gives everything in it to the user to remove, including the files that hard links in it share with others (which only the host can put there). In :sudo mode, its directories belong to root, so this uses sudo then.

Sandbox.register_multiarch(config::SandboxConfig)

Registers with the kernel (binfmt_misc) the QEMU interpreters that running executables of config.multiarch in the sandbox needs, unless they already are. Uses sudo.
